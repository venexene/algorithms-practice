# Next Greater Element I

## Инсайт

При проходе по `nums2` слева направо текущий элемент может стать ответом сразу для нескольких предыдущих элементов. Достаточно хранить в стеке те числа, для которых ближайший больший элемент справа ещё не найден.

## Решение

### Монотонный стек + хеш-таблица — O(n + m), O(n + m)

Здесь `n = len(nums2)`, `m = len(nums1)`. Стек хранит значения в строго убывающем порядке снизу вверх: по условию задачи все элементы уникальны.

1. Проходим по `nums2`. Пока текущий элемент больше вершины стека, записываем его в `greaters` как ответ для вершины и удаляем вершину.
2. Добавляем текущий элемент в стек: его ответ ещё неизвестен.
3. Проходим по `nums1` и собираем результат в исходном порядке. Если число есть в `greaters`, берём найденный ответ; иначе записываем `-1`.

## Почему это ближайший больший элемент

Число остаётся в стеке, пока справа не встретится элемент больше него. Если бы больший элемент встретился раньше, число уже было бы удалено из стека. Поэтому элемент, который снимает число с вершины, — первый больший справа.

Убывающий порядок позволяет проверять только вершину: если текущий элемент не больше вершины, он не больше и остальных элементов стека. Если больше — снимаем вершину и продолжаем проверку.

## Что важно запомнить

- Нужен именно **первый больший справа**, а не максимальный элемент справа.
- Вложенный цикл не даёт `O(n²)`: каждое число добавляется в стек один раз и удаляется не более одного раза. Обработка `nums2` суммарно занимает `O(n)`.
- Числа, оставшиеся в стеке после прохода, не имеют большего элемента справа. Записывать для них `-1` в карту не обязательно: отсутствие ключа обрабатывается при сборке результата.
- Проверка `ok` отличает отсутствие ответа от нулевого значения карты.
- Хранить значения вместо индексов и использовать карту `число → ответ` позволяет уникальность элементов `nums2`. При повторяющихся значениях ответ мог бы зависеть от позиции.
- Итоговое время — `O(n + m)` при обычной оценке операций хеш-таблицы. Стек и карта занимают `O(n)`, результат — `O(m)`: всего `O(n + m)`, без учёта результата — `O(n)`.

## Оценка

Решение корректно для условий задачи: элементы уникальны, `nums1` — подмножество `nums2`. Подход оптимален по времени, логических ошибок при разборе не обнаружено. Трудности при решении не обсуждались.

Небольшие улучшения без изменения алгоритма: получать значение и `ok` одним обращением к карте вместо двух; заранее выделять место под `len(nums1)` элементов результата.
