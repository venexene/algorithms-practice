# Increasing Triplet Subsequence

## Решение

### Один проход — O(n), O(1)

`first` хранит минимальное число среди уже просмотренных. `second` хранит минимальный возможный последний элемент возрастающей пары, найденной в просмотренном префиксе. Для очередного числа:

- Если оно не больше `first`, обновляем `first`.
- Иначе, если оно не больше `second`, обновляем `second`: перед ним уже было меньшее число.
- Иначе найдено число больше `second`, а значит, существует возрастающая тройка индексов.

## Что важно запомнить

- Нужна **подпоследовательность**, поэтому числа могут стоять не подряд, но их индексы должны возрастать.
- Сравнения `<=` не позволяют равным числам образовать строго возрастающую пару или тройку.
- `first` может обновиться уже после `second`. Это не ломает решение: когда `second` был установлен, перед ним существовало подходящее меньшее число. Текущие значения `first` и `second` не обязаны быть элементами одной пары.
- Время `O(n)` — один проход; дополнительная память `O(1)` — две переменные.

## Оценка

Решение корректно и достигает оптимальной асимптотики. Например, для `[2, 1, 5, 0, 4, 6]` оно находит тройку `0 < 4 < 6`, хотя минимум обновляется после появления первой пары. Для массива из одинаковых чисел результат будет `false`. В текущем примере `[0, 4, 2, 1, 0, -1, -3]` результат также `false`.

Логических ошибок не обнаружено. Форматирование `increasingTriplet` отличается от стандартного `gofmt`; на корректность это не влияет.
