# String Compression

## Решение

### Два указателя — O(n) по времени, O(1) дополнительной памяти

`start` и `end` ограничивают текущую группу одинаковых символов: `end` сдвигается до первого отличающегося символа. `write` указывает, куда записывать сжатый результат. Для группы длины 1 записывается только символ; для более длинной группы — символ и десятичные цифры её длины. Возвращается длина заполненного префикса `chars`.

Запись на месте безопасна: представление группы не длиннее самой группы, поэтому после обработки группы `write <= end`. Следующая группа ещё не перезаписана.

## Что важно запомнить

- Сжимаются **последовательные группы**, а не все одинаковые символы во всём массиве. Например, две группы `a` по разные стороны от `b` обрабатываются отдельно.
- Для группы длины 1 цифра `1` не записывается. Многозначный счётчик записывается по одной цифре: десять символов `a` превращаются в `a10`.
- `byte('0' + digit)` превращает цифру от 0 до 9 в её текстовый символ. Просто `byte(digit)` записал бы числовой байт, а не символ цифры.
- Порядок проверок в цикле важен: условие `end < len(chars)` не даёт обратиться за границу слайса.
- Время `O(n)`: чтение групп и запись результата линейны по длине входа.

## Замечания к первому варианту и исправления

- Первый вариант создавал строку через `strconv.Itoa` и затем временный `[]byte` с цифрами счётчика. Для произвольной длины входа это `O(log n)` временной памяти. Теперь цифры записываются сразу в исходный `chars`, без промежуточного слайса.
- Внутри `compress` был отладочный вывод результата. Он убран: функция только меняет входной слайс и возвращает длину результата.
- Локальное присваивание `chars = chars[:write]` не меняло длину слайса у вызывающего кода. Оно убрано, но `len(chars[:write])` всё ещё просто равно `write`; можно возвращать `write` напрямую.
- При первой попытке записи цифр в цикле уменьшался `k`, а делитель вычислялся по неизменному `e`. Поэтому группа из 12 символов превращалась в `a10` вместо `a12`. Сейчас `e` уменьшается на каждом шаге, и разряды обрабатываются по порядку.

## Оценка текущего решения

Логика сжатия корректна для обычных размеров входа, включая пустой слайс, одиночные символы и многозначные счётчики. Дополнительная память теперь `O(1)`.

Для определения старшего разряда и степени десятки используются `math.Log10` и `math.Pow` с `float64`. При очень больших целых числах округление с плавающей точкой может дать неверный разряд. Целочисленный делитель надёжнее и избавляет от повторного вычисления степени. Для небольших ограничений задачи эта проблема не проявляется.
