# Find the Difference of Two Arrays

## Решение

### Хеш-сеты — O(n + m), O(n + m)

Здесь `n = len(nums1)`, `m = len(nums2)`. Сначала собираем уникальные значения `nums1` в `mp1`. При проходе по `nums2` наполняем `mp2` и добавляем в `set2` значения, которых нет в `mp1`. Затем проходим по `nums1` и добавляем в `set1` значения, которых нет в `mp2`. Из `set1` и `set2` собираем два списка ответа.

## Что важно запомнить

- Ответ — две **разности множеств**: `nums1 \ nums2` и `nums2 \ nums1`. Проверять наличие элемента удобно через `map[int]struct{}`.
- `set1` и `set2` убирают повторы: даже если число встречается во входном массиве несколько раз, в ответе оно будет один раз.
- Для проверки `nums1 \ nums2` сначала нужно знать все значения `nums2`, поэтому проход по `nums1` выполняется после заполнения `mp2`.
- Порядок элементов при обходе `map` в Go не гарантирован. Это подходит для задачи, где элементы каждого списка ответа могут идти в любом порядке.
- В среднем время `O(n + m)`: несколько линейных проходов и операции с хеш-таблицами. Память `O(n + m)` на множества и результат.

## Оценка

Решение корректно: оно находит значения, присутствующие только в одном из массивов, и исключает дубликаты. На примере `nums1 = [1, 2, 3]`, `nums2 = [2, 4, 6]` получается `[[1, 3], [4, 6]]` с точностью до порядка элементов.

Четыре множества делают шаги явными, хотя можно обойтись меньшим числом структур. Циклы `for k, _ := range ...` можно записать короче как `for k := range ...`. Если в одной из частей ответа нет элементов, соответствующий внутренний слайс останется `nil`; это стоит учитывать, если результат сравнивается с пустым слайсом через `reflect.DeepEqual` или сериализуется в JSON. Логических ошибок при разборе не обнаружено; трудности при решении не обсуждались.
